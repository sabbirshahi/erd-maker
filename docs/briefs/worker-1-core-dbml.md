# worker-1 — core-dbml (Phase 1 + M1/M2)

Plan sections: §3 Phase 1, Phase 3 (M1 SQL import, M2 SQL export), §2 IR + sync rules.

## Deliverables
1. `src/core/dbml/parse.ts` + `index.ts`: `parseDbml(text)` using `@dbml/core` (`new Parser().parse(text, 'dbml')` — wrap in try/catch; `CompilerError` has `.diags[]` with `location.start.line/column` and `message`). Walk `database.schemas[].tables[]` (fields: `name`, `type.type_name`/`type.args`, `pk`, `unique`, `not_null`, `increment`, `dbdefault {type,value}`, `note`), table `indexes[]` (`columns[]`, `pk`, `unique`, `name`, `type`), `refs[]` (`endpoints[]` with `tableName`, `schemaName`, `fieldNames[]`, `relation` '1'|'*'; `onDelete`, `onUpdate`, `name`), `enums[]` (`values[]`), and `database.note`, `project`, `tableGroups` → `project.passthrough` verbatim where possible. Inline `[ref: > t.c]` refs come out as normal refs. Map endpoint relations to kind: `*→1` = `>`, `1→*` = `<`, `1→1` = `-`, `*→*` = `<>`. Column types written as in source (`varchar(255)`, `decimal(10,2)`), enum names kept as the type.
2. `src/core/dbml/generate.ts`: deterministic, idempotent generator. Order: project block (if any), enums, tables (source order), refs. Two-space indent, settings in `[pk, increment, not null, unique, default: x, note: 'x']` order, inline notes with single quotes escaped, `indexes { }` block, `Note:` block for tables. Ref line: `Ref name: a.b > c.d [delete: cascade, update: no action]` (name optional). Composite: `(a, b)`.
3. `src/core/reconcile.ts`: id preservation by name path (schema.table.column, ref by endpoints, enum by name, index by column set), then rename heuristic (same table, same column count, exactly one column name differs → keep that column's id). Tables: if a table disappeared and a new one appeared with identical column names → rename.
4. `src/core/sql/index.ts`: `importSql(sql, dialect|'auto')` via `import { importer } from '@dbml/core'` → `importer.import(sql, format)`; pre-clean vendor noise (MySQL `ENGINE=…`, `COLLATE`, backticks OK; Postgres `CREATE EXTENSION`, `SET`, `COMMENT ON` are fine to strip; auto-detect by keywords). `exportSql(schema, dialect)`: `ModelExporter.export(new Parser().parse(generateDbml(schema),'dbml'), 'postgres'|'mysql')`; sqlite = postgres output through a type-rewrite table (`serial`→`INTEGER PRIMARY KEY AUTOINCREMENT`, `timestamp`→`TEXT`, `boolean`→`INTEGER`, drop `CREATE TYPE ... AS ENUM` → CHECK constraint, etc.). Return diagnostics instead of throwing.
5. Fixtures in `tests/fixtures/`: `blog.dbml` (copy of `src/examples/blog.dbml`), `ecommerce.dbml` (dbdiagram's official e-commerce example, ~6 tables), `kitchen_sink.dbml` (enums, composite pk via indexes, all four ref kinds, inline refs, schema-qualified `public.x`, defaults incl. `` `now()` ``, notes, Project + TableGroup), `sql/ecommerce.postgres.sql`.
